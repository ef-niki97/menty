# Menty — панель ментора

Сайт для ведения учеников: профиль, цели, оценка компетенций с радар-диаграммой, история портфолио и CV.
Фронтенд — чистый HTML/CSS/JS (папка `public/`), бэкенд — один Cloudflare Worker (`src/worker.js`)
с базой D1 (карточки) и хранилищем R2 (файлы CV и договоров, до 10 МБ на файл). Многопользовательский: у каждого ментора свои данные (`owner_id`).
Вход через Google и Яндекс, регистрация новых менторов по приглашениям; пароль администратора остаётся запасным входом.

## Деплой на Cloudflare (через GitHub, без установки Node)

1. **База.** Уже создана: D1 `menty`, её ID прописан в `wrangler.toml`. Структуру создают миграции (см. «Миграции базы» ниже).
2. **Проект.** Workers & Pages → *Create* → *Import a repository* → выберите `menty`.
   Build command оставьте пустым, Deploy command: `npx wrangler deploy`.
3. **Секреты.** Worker `menty` → Settings → Variables and Secrets → добавьте как **Secret**:
   - `ADMIN_PASSWORD` — нужен только для запасного входа по паролю (по умолчанию он выключен);
   - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` и `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` — ключи входа (см. ниже);
   - переменные (не секреты, можно в `wrangler.toml`): `SIGNUP_MODE` (`invite` по умолчанию, `open` или `closed`),
     `MAX_STUDENTS` (учеников на ментора, 100) и `QUOTA_MB` (файлов на ментора, 200). У администратора лимитов нет.
4. Откройте `https://menty.work` и войдите: через Google/Яндекс с почтой администратора (`ADMIN_EMAIL`) либо по паролю.

### Вход через Google и Яндекс

Сайт работает на `https://menty.work`. Redirect URI для обоих: `https://menty.work/api/auth/google/callback` и `https://menty.work/api/auth/yandex/callback`
(входить нужно именно с этого адреса: адрес возврата берётся из адресной строки).
Адрес `www.menty.work` тоже подключён и перенаправляет на `menty.work`: страницы — скриптом в `index.html`, запросы `/api/*` — кодом Worker.

- **Google:** Google Cloud Console → APIs & Services → Credentials → *OAuth client ID* (Web application),
  укажите Redirect URI; на экране согласия достаточно scope `openid email profile`.
- **Яндекс:** oauth.yandex.ru → *Создать приложение* → платформа «Веб-сервисы», Callback URI как выше,
  доступы: «Доступ к адресу электронной почты» и «Доступ к логину, имени и фамилии».

Пока ключи не заданы, кнопки провайдера на странице входа не показываются.
Вход по паролю выключен. Запасной путь на случай проблем с провайдерами: задайте переменную `ALLOW_PASSWORD_LOGIN=1` и секрет `ADMIN_PASSWORD`, на странице входа появится форма для администратора. Аккаунт администратора удалить нельзя.

### Миграции базы

Структура базы описана SQL-файлами в `migrations/` (`0001_baseline.sql`, дальше `0002_…`, `0003_…`). Код Worker сам таблицы не создаёт и не меняет.
Каждый файл применяется один раз, Cloudflare помнит применённые. Уже применённые файлы не правят: любое изменение схемы — новый файл.

- **Новая база:** `npm run migrate` (то есть `wrangler d1 migrations apply menty --remote`).
- **Автоматически при деплое:** в настройках сборки Cloudflare (Settings → Builds) поставьте Deploy command `npm run release`
  и дайте токену сборки право **D1: Edit** (My Profile → API Tokens → токен сборки). Без этого права команда миграции упадёт, поэтому до настройки оставлен прежний `npx wrangler deploy`.
- **Пока автоприменения нет:** новую миграцию можно выполнить прямо в D1 (панель Cloudflare → D1 → `menty` → Console) и вручную пометить: `INSERT INTO d1_migrations (name) VALUES ('0002_….sql')`.

Боевая база уже соответствует `0001_baseline.sql`, поэтому его применение ничего не меняет и просто фиксирует начальную точку.

### Файлы в R2

Файлы лежат в R2 (бакет `menty-files`, привязка `FILES` в `wrangler.toml`), ключ объекта — `владелец/id`. Без привязки Worker работает по-старому:
куски base64 в D1. Старые файлы при первом скачивании сами переезжают в R2; остальные переносит пункт «Перенести файлы в R2» в меню администратора.

### Первый запуск после обновления

При первом запросе база сама переводится в многопользовательскую: все существующие ученики, воркспейсы, ссылки и файлы
становятся данными администратора (`ADMIN_EMAIL`). Старые сессии сбрасываются — нужно войти заново.

Дальше каждый `git push` в `main` обновляет сайт автоматически.

## Структура

```
wrangler.toml       настройки Worker: статика, D1, почта администратора
src/worker.js       API: /api/auth/*, /api/students, /api/files, /api/invites …
public/index.html
public/css/         tokens.css (брендовый цвет — чёрный, --ink), app.css
public/js/config.js грейды, статусы, список компетенций  ← правится здесь
public/js/api.js    обёртка над fetch
public/js/store.js  данные ↔ сервер (единственное место работы с данными)
public/js/auth.js   вход/выход
public/js/views/*   экраны: login, students, wizard, student
public/js/demo.js   демо-ученики (кнопка на пустом экране)
```

## Экраны

`/login` · `/students` (список) · `/students/new` (добавление) · `/student/:id` (карточка) · `/student/:id/assess` (новая оценка) · `/s/:token` (публичная ссылка)

## Безопасность

- Ключи провайдеров и пароль администратора лежат только в секретах Cloudflare, в репозитории их нет.
- Сессия — случайный токен в куке `HttpOnly; Secure; SameSite=Strict` на 30 дней; в базе хранится только его SHA-256.
- Вход через OAuth с PKCE и проверкой `state`; почта провайдера должна быть подтверждена.
- Каждый запрос ограничен данными владельца: ученики, воркспейсы, ссылки и файлы чужих менторов недоступны и не перезаписываются.
- Публичные ссылки (просмотр, самооценка, отзыв) работают по случайным токенам; договор и личная заметка не публикуются.
- Удаление аккаунта (меню профиля) стирает все данные ментора.
- Неверный пароль отвечает с задержкой. Файлы отдаются как вложения и не исполняются в браузере.
- Резервная копия (меню профиля) содержит карточки, но **не файлы CV**.

## Локальный просмотр интерфейса

Полноценно (с API) локально запускается командой `npx wrangler dev` (нужен Node.js) — понадобятся
`ADMIN_PASSWORD` и `SESSION_SECRET` в файле `.dev.vars`.
