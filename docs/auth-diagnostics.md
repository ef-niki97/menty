# Диагностика медленного входа

Изменения начинают работать на основном сайте только после отдельного согласованного деплоя.
Локальный запуск проверяет инструменты измерения, но не воспроизводит сетевой путь Google → Cloudflare → D1 рабочего сайта.

## Повторный вход

1. Перед входом откройте DevTools: Network и Console, включите Preserve log.
2. Войдите через Google обычным способом и дождитесь кабинета.
3. В Network найдите `/api/auth/google/callback`. В ответе есть `Server-Timing` и `X-Menty-Request-Id`.
4. В Console найдите `[Menty startup]`. Это сводка проверки сессии, загрузки данных и показа страницы.
   Текущая сводка также доступна как `window.__mentyDiagnostics`.
5. Сопоставьте ID ответа callback с записью `auth_timing` в логах Worker.
   Логи можно смотреть в Cloudflare или через `npx wrangler tail menty --format json` во время повторного входа.

Не нужен полный HAR: он может содержать cookies и OAuth-коды. Для разбора достаточно ID запроса,
длительностей `Server-Timing` и объекта `window.__mentyDiagnostics`.

## Как читать замеры

- `oauth_token`, `oauth_profile`: запросы Worker к провайдеру, включая чтение ответа.
- `user_db`: поиск/создание пользователя, проверка приглашения и основного воркспейса.
- `session_db`: создание сессии.
- `session_lookup`: проверка сессии при запросе API.
- `students_db`, `workspaces_db`: получение данных кабинета и подготовка JSON.
- Серверный `total`: вся обработка запроса Worker. Он не включает путь браузера до Cloudflare.
- Браузерный `duration_ms`: запрос API целиком, включая передачу и разбор JSON.
- `script_ready_ms`: время от начала навигации до запуска инициализации приложения.
- `auth_ms`, `data_ms`, `render_ms`: проверка сессии, начальная загрузка данных, создание страницы.
- `ready_ms`: время от начала навигации до первой возможности показать созданную страницу.

Большие `oauth_*` указывают на участок Worker ↔ провайдер, `*_db` на работу с базой,
а большой разрыв между серверным `total` и браузерным `duration_ms` требует проверки сети и браузера.
Все браузерные времена относятся к странице после редиректа, а не ко всему входу с момента нажатия кнопки Google.

Диагностика не меняет правила входа, cookies, приглашения и редиректы. Логи не содержат
почту, профиль, OAuth-код, токены, код приглашения или содержимое базы.

## Проверка локально

`node --test tests/auth-diagnostics.test.mjs`

Тесты используют подставные Google и базу; реальная авторизация и рабочие данные не затрагиваются.
